# Информационная система составления расписания занятий

## 1. Описание проекта

**Информационная система расписания** — веб-приложение для просмотра и управления расписанием занятий учебного заведения.

Система предназначена для преподавателей, методистов и администраторов. Она позволяет просматривать расписание, формировать его по учебным группам, дням недели, учебным дисциплинам, преподавателям, кабинетам и времени занятий.

В расписании предусмотрены разные формы проведения занятий: лекции, практические занятия и мероприятия. Для мероприятий вместо учебной дисциплины может указываться отдельное название.

В приложении предусмотрены страницы регистрации и авторизации, личный кабинет, отдельная страница методиста и административная часть для управления справочниками и ролями пользователей.

Проект построен на Laravel и использует MySQL для хранения данных.

## 2. Назначение и задачи системы

Основные задачи проекта:

- Предоставление пользователям доступа к расписанию.
- Отображение расписания занятий по учебным группам и дням недели.
- Хранение информации о преподавателях и ролях пользователей.
- Хранение учебных групп и направлений подготовки (специальностей).
- Хранение списка дисциплин, аудиторий и временных интервалов занятий.
- Формирование и сохранение расписания.
- Управление справочными данными через административную часть.
- Разграничение возможностей пользователей по ролям.

## 3. Роли пользователей

В базе данных предусмотрены три роли:

| Роль | Назначение |
|---|---|
| Преподаватель | Просмотр расписания и использование пользовательской части системы |
| Методист | Работа со страницей методиста и отправка данных расписания |
| Администратор | Управление справочниками системы и назначение ролей пользователям |

Роль пользователя хранится в поле `user.id_role` и связана с таблицей `user_role`.

> В предоставленных маршрутах явно присутствуют страницы для преподавателя (личный кабинет), методиста и администратора. Точный перечень разрешений каждой роли и правила ограничения доступа должны определяться по middleware и коду контроллеров; в самих маршрутах middleware-группы не указаны.

## 4. Функциональность и маршруты

### 4.1. Публичные и пользовательские страницы

| Метод | Маршрут | Имя маршрута | Назначение |
|---|---|---|---|
| GET | `/` | `index` | Главная страница |
| GET | `/table` | `table` | Просмотр таблицы расписания |
| GET | `/register` | `register` | Страница регистрации |
| GET | `/login` | `login` | Страница авторизации |
| GET | `/lk` | `lk` | Личный кабинет пользователя |
| GET | `/methodist` | `methodist` | Страница методиста |
| GET | `/admin` | `admin` | Страница администратора |

### 4.2. Регистрация, авторизация и выход

| Метод | Маршрут | Имя маршрута | Назначение |
|---|---|---|---|
| POST | `/register` | `createUser` | Обработка регистрации нового пользователя |
| POST | `/auth` | `auth` | Проверка данных для входа |
| GET | `/logout` | `logout` | Выход пользователя из системы |

Регистрация и авторизация обрабатываются контроллером `UserController`. Данные пользователей сохраняются в таблице `user`, а назначение роли определяется полем `id_role`.

### 4.3. Работа методиста с расписанием

| Метод | Маршрут | Имя маршрута | Назначение |
|---|---|---|---|
| POST | `/schedule` | `schedule` | Отправка данных для формирования или сохранения расписания |

Маршрут направляет запрос в метод `schedule` контроллера `MethodistController`.

В базе данных для хранения расписания предусмотрена таблица `schedule`. Запись расписания связывает день недели, номер занятия, аудиторию, учебную группу, форму занятия, дисциплину и преподавателя. Для мероприятий дополнительно предусмотрено поле `name_meeting`.

### 4.4. Административное управление

Административные операции выполняются через `AdminController`.

| Метод | Маршрут | Имя маршрута | Назначение |
|---|---|---|---|
| POST | `/admin` | `admin` | Обработка POST-запроса на административную страницу |
| POST | `/group` | `addGroup` | Добавление учебной группы |
| POST | `/speciality` | `addSpeciality` | Добавление специальности |
| POST | `/item` | `addItem` | Добавление учебной дисциплины |
| POST | `/cabinet` | `addCabinet` | Добавление аудитории |
| POST | `/role` | `changeRole` | Изменение роли пользователя |
| DELETE | `/speciality` | `delSpeciality` | Удаление специальности |
| DELETE | `/group` | `delGroup` | Удаление учебной группы |
| DELETE | `/item` | `delItem` | Удаление дисциплины |
| DELETE | `/cabinet` | `delCabinet` | Удаление аудитории |

Таким образом, административная часть предусматривает управление основными справочниками, используемыми при составлении расписания, а также изменение ролей пользователей.

**Примечание:** маршрут `GET /admin` и маршрут `POST /admin` имеют одинаковый URI, но обрабатывают разные HTTP-методы. В обоих случаях используется имя `admin`; это стоит учитывать при генерации URL по имени маршрута.

## 5. Структура базы данных

База данных проекта называется `schedule`. В SQL-дампе определены следующие таблицы.

### 5.1. `user` — пользователи

Хранит учётные и персональные данные пользователей системы.

| Поле | Тип | Описание |
|---|---|---|
| `id_user` | INT | Уникальный идентификатор пользователя |
| `id_role` | INT | Идентификатор роли |
| `last_name` | VARCHAR(255) | Фамилия |
| `name` | VARCHAR(255) | Имя |
| `patronymic` | VARCHAR(255) | Отчество |
| `email` | VARCHAR(255) | Электронная почта |
| `login` | VARCHAR(255) | Логин |
| `password` | VARCHAR(255) | Хеш пароля |

Поля `email` и `login` имеют уникальные индексы. Поле `id_role` связано с таблицей `user_role`.

### 5.2. `user_role` — роли пользователей

Содержит список доступных ролей.

| Поле | Тип | Описание |
|---|---|---|
| `id_role` | INT | Уникальный идентификатор роли |
| `name_role` | VARCHAR(255) | Название роли |

В дампе присутствуют роли: «Преподаватель», «Методист» и «Администратор».

### 5.3. `speciality` — специальности

Содержит направления подготовки, к которым относятся учебные группы.

| Поле | Тип | Описание |
|---|---|---|
| `id_speciality` | INT | Уникальный идентификатор специальности |
| `name_speciality` | VARCHAR(255) | Название специальности |

### 5.4. `group` — учебные группы

Хранит список учебных групп и информацию об их специальностях.

| Поле | Тип | Описание |
|---|---|---|
| `id_group` | INT | Уникальный идентификатор группы |
| `id_speciality` | INT | Идентификатор специальности |
| `name_group` | VARCHAR(255) | Название учебной группы |

Поле `id_speciality` связано с таблицей `speciality`.

### 5.5. `item` — учебные дисциплины

Содержит список дисциплин, которые могут быть указаны в расписании.

| Поле | Тип | Описание |
|---|---|---|
| `id_item` | INT | Уникальный идентификатор дисциплины |
| `name_item` | VARCHAR(255) | Название дисциплины |

### 5.6. `cabinet` — аудитории

Хранит список учебных кабинетов и аудиторий.

| Поле | Тип | Описание |
|---|---|---|
| `id_cabinet` | INT | Уникальный идентификатор аудитории |
| `name_cabinet` | VARCHAR(255) | Номер или название аудитории |

### 5.7. `day_week` — дни недели

Содержит дни недели, используемые при формировании расписания.

| Поле | Тип | Описание |
|---|---|---|
| `id_day` | INT | Уникальный идентификатор дня |
| `name_day` | VARCHAR(11) | Название дня недели |

В предоставленном дампе присутствуют дни с понедельника по субботу.

### 5.8. `time_lesson` — время занятий

Содержит временные интервалы учебных занятий.

| Поле | Тип | Описание |
|---|---|---|
| `id_lesson` | INT | Уникальный идентификатор временного интервала |
| `start_time_lesson` | TIME | Время начала занятия |
| `end_time_lesson` | TIME | Время окончания занятия |

В примерах данных определено семь временных интервалов — с 08:30 до 20:30.

### 5.9. `form` — формы занятий

Содержит варианты формы проведения занятия.

| Поле | Тип | Описание |
|---|---|---|
| `id_form` | INT | Уникальный идентификатор формы |
| `name_form` | VARCHAR(20) | Название формы |

В дампе представлены три формы:

- Лекция;
- Практика;
- Мероприятие.

### 5.10. `schedule` — расписание

Основная таблица системы. Хранит записи расписания для учебных групп.

| Поле | Тип | Описание |
|---|---|---|
| `id_schedule` | INT | Уникальный идентификатор записи расписания |
| `id_day` | INT | Идентификатор дня недели |
| `id_lesson` | INT | Идентификатор временного интервала |
| `id_cabinet` | INT, NULL | Идентификатор аудитории |
| `id_group` | INT | Идентификатор учебной группы |
| `id_form` | INT | Идентификатор формы занятия |
| `id_item` | INT, NULL | Идентификатор учебной дисциплины |
| `id_teacher` | INT | Идентификатор преподавателя (пользователя) |
| `name_meeting` | VARCHAR(255), NULL | Название мероприятия |

Поля `id_cabinet` и `id_item` допускают значение `NULL`. Это позволяет создавать записи без назначенной аудитории или дисциплины. В частности, в примерах данных для формы «Мероприятие» дисциплина не указывается, а название мероприятия хранится в `name_meeting`.

## 6. Связи между таблицами

В SQL-дампе определены следующие внешние ключи:

| Основная таблица | Поле | Связанная таблица | Поле | Смысл связи |
|---|---|---|---|---|
| `user` | `id_role` | `user_role` | `id_role` | Пользователь имеет одну роль |
| `group` | `id_speciality` | `speciality` | `id_speciality` | Группа относится к специальности |
| `schedule` | `id_lesson` | `time_lesson` | `id_lesson` | Запись расписания относится к временному интервалу |
| `schedule` | `id_day` | `day_week` | `id_day` | Запись расписания относится к дню недели |
| `schedule` | `id_cabinet` | `cabinet` | `id_cabinet` | Для занятия может быть назначена аудитория |
| `schedule` | `id_group` | `group` | `id_group` | Запись расписания относится к учебной группе |
| `schedule` | `id_item` | `item` | `id_item` | Для занятия может быть указана дисциплина |
| `schedule` | `id_teacher` | `user` | `id_user` | Занятие связано с преподавателем |
| `schedule` | `id_form` | `form` | `id_form` | Для занятия задаётся форма проведения |

Для связей `group → speciality`, `user → user_role` и большинства связей таблицы `schedule` в SQL указаны действия `ON DELETE CASCADE ON UPDATE CASCADE`. Для связи преподавателя с пользователем каскадные действия не заданы. Для формы занятия также не заданы каскадные действия.

### 6.1. Общая схема связей

```text
user_role
   |
   | id_role
   v
 user
   ^
   | id_teacher
   |
schedule
   |------ day_week
   |------ time_lesson
   |------ cabinet
   |------ group ------ speciality
   |------ item
   |------ form
```

## 9. Общая логика работы системы

1. Пользователь открывает сайт.
2. При необходимости пользователь регистрируется или входит в систему.
3. После входа пользователь может перейти в личный кабинет.
4. Преподаватель использует пользовательскую часть для работы с расписанием.
5. Методист открывает специальную страницу и отправляет данные расписания через маршрут `/schedule`.
6. Администратор управляет справочниками: учебными группами, специальностями, дисциплинами и аудиториями.
7. Администратор при необходимости изменяет роли пользователей.
8. Расписание хранится в таблице `schedule` и связывается с данными справочников и пользователями-преподавателями.

## 10. Итог

Проект представляет собой веб-систему для организации и просмотра расписания учебных занятий. В основе приложения находится таблица `schedule`, которая объединяет сведения о времени, днях недели, учебных группах, преподавателях, аудиториях, дисциплинах и формах занятий.

Система предусматривает три роли пользователей — преподаватель, методист и администратор. Для управления данными предусмотрена административная часть, а для работы с расписанием — отдельная страница методиста и пользовательская страница просмотра.
